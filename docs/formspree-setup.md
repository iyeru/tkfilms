# Contact フォームの送信先を用意する（Formspree）

**この作業は shinta が行う。** 済んだら `src/content.ts` の 2 行を書き換えるだけで
フォームが実際に届くようになる。

## なぜ外部サービスが要るのか

このサイトは GitHub Pages で配信している。**Pages は静的ファイルを返すだけでサーバを
持たない**ため、サイト自身がメールを送ることはできない。

そこで「フォームの中身を受け取って、shinta のメールへ転送する」だけの外部サービスを
1 つ挟む。ページ側は `fetch` でそこへ投げるだけなので、**画面は遷移しないまま
「送信中」「ありがとうございました」「送信できませんでした」を出せる。**

Formspree を選んだのは、静的サイト向けで無料枠があり、`fetch` からの JSON 送信に
正式対応しているため。同種の Getform / Basin でも同じ形で差し替えられる
（送信先 URL を変えるだけ）。

## 手順

### 1. アカウントを作る

<https://formspree.io/> → Sign up。GitHub アカウントでも作れる。

**受信に使うメールアドレスで登録する。** ここに問い合わせが転送される。

### 2. フォームを 1 つ作る

ダッシュボードで **New Form**。

| 項目 | 入れる値 |
|---|---|
| Form Name | `tkfilms Contact`（何でもよい。管理画面の表示名） |
| Send emails to | 問い合わせを受け取りたいアドレス |

作ると `https://formspree.io/f/xxxxxxxx` という **エンドポイント URL** が出る。
この `xxxxxxxx` の部分がフォームの ID。**これを控える。**

> このURLは公開して問題ない。静的サイトである以上、ブラウザから見えるところに
> 必ず出るもので、隠す前提の値ではない。

### 3. メールアドレスを確認する

Formspree は **最初の 1 通目を送るまでフォームを有効にしない。** 登録直後に届く
確認メール（Confirm your email）のリンクを踏んでおく。

### 4. `src/content.ts` に貼る

`contact:` の中の 2 行を書き換える。

```ts
contact: {
  ...
  // ↓ 手順2で控えた URL に差し替える
  endpoint: 'https://formspree.io/f/xxxxxxxx',
  // ↓ 送信に失敗した人へ案内するアドレス。出したくなければ null のままでよい
  fallbackEmail: 'hello@tkfilms.jp',
  ...
}
```

`endpoint` が `null` のあいだ、フォームは**送信せず必ず「送信できませんでした」を出す。**
黙って成功したふりをさせないための作りなので、貼り忘れれば画面ですぐ分かる。

### 5. 設定を 2 か所だけ見ておく

ダッシュボードのフォーム設定（Settings）で次を確認する。

- **reCAPTCHA / captcha** … **オフ**にする。オンだと `fetch` からの送信が
  「captcha を通っていない」として弾かれ、画面に「送信できませんでした」が出る。
  代わりに、フォームには見えない罠の入力欄（`_gotcha`）を仕込んであり、
  bot が埋めた送信は Formspree 側で捨てられる。
- **Allowed domains（Restrict to domain）** … 使うなら `tkfilms.jp` を入れる。
  他所のサイトに貼られて無料枠を食い潰されるのを防げる。
  **ただし入れると `localhost` からは送れなくなる**ので、手元で試すなら後から入れる。

## 届くことを確かめる

design-review の完了条件は「**本番相当の環境で 1 回、実際に手元へ届くこと**」。
手元の `npm run dev` ではなく、公開されている <https://tkfilms.jp/#contact> で試す。

1. 4 項目すべて埋めて **Send** を押す
2. ボタンが `Sending` → `Thank you` に変わり、**ページが遷移しない**
3. 入力欄が空に戻る
4. 下に「お問い合わせを受け付けました。」が出る
5. **登録したメールアドレスに実際に届く**（件名は入力した Subject そのまま）

わざと失敗させて確かめたいときは、`endpoint` を存在しない URL にすれば
「送信できませんでした」の表示を確認できる。

## 無料枠と、超えたときの挙動

- 無料プラン: **月 50 件**まで（月初にリセット）
- 超えると送信が拒否され、画面には「送信できませんでした」が出る
  （`fallbackEmail` を入れておけば、そこにメールアドレスの案内も並ぶ）

自己紹介サイトの問い合わせで月 50 件を超えることは考えにくいが、
**上限に達しても気付けるのはフォームを送った人だけ**という点は覚えておく。
心配なら Formspree の通知設定でメールを受け取れる。

## 送られる中身

| フィールド名 | 画面上の入力欄 | 用途 |
|---|---|---|
| `name` | Your Name | 本文に入る |
| `email` | Your Email | 本文に入る。**返信先（Reply-To）にも使われる** |
| `_subject` | Subject | **メールの件名**になる |
| `message` | Message | 本文に入る |
| `_gotcha` | （見えない） | bot 判定用の罠。人が埋めることはない |

`_` で始まる 2 つは Formspree の特別な名前。**他サービスへ移すときはここが変わる**
（Getform なら件名は管理画面側の設定になる）。実装は `src/sections/Contact.tsx`。
